## T1：配置与连接契约

已实现地址规范化、后端范围标识、偏好保存及恢复默认、无凭据健康检查、旧检查失效、HTTPS 与同来源重定向限制。默认本机连接继续校验应用包证书，自定义连接的其他证书交给系统信任处理。

定向验证命令：`swift test --package-path macos --filter 'BackendAddressTests|APIClientTests'`。2 项 XCTest 与 8 项 Swift Testing 通过，非法地址覆盖 15 组参数。覆盖请求目标和无 Authorization、失败重试、输入修改后的旧结果、配置重建以及默认／自定义数据范围。

首次测试复现 URLSession 取消与任务创建竞争，进程抛出 `Task created in a session that has been invalidated`。调整为先关闭客户端接收新请求、取消已有任务，并在对象释放时终止自有会话；重验通过。失败与修复日志分别为 `.runtime/backend-address-2026-10-30/t1-tests.log` 和 `t1-tests-fixed.log`。

本阶段属于核心契约与模拟网络验证；原生运行态、真实 TLS 和登录切换结果见 G1。

## T2：运行态与数据隔离

运行态工厂按后端建立账号、库、专注和同步控制器。默认地址采用原目录及原登录键；自定义来源使用地址摘要目录和独立记住登录键、钥匙串服务名。切换先暂停并落盘，再停用旧账号和客户端；所有旧回调都核对控制器身份。

定向账号、专注和同步验证通过：5 项 XCTest 与 15 项 Swift Testing。随后增加暂停落盘失败断言，完整核心回归为 33 项 XCTest 与 37 项 Swift Testing，共 70 项通过。日志为 `.runtime/backend-address-2026-10-30/t2-tests.log` 与 `core-tests.log`。临时数据库验证同账号标识下不同后端的现场、事件及上传队列隔离，切回后可恢复暂停现场。

原生编译通过，日志为 `t2-build.log`。早期真实 TLS 探测经正式连接工厂，访问 `https://localhost:8447/health` 与 `https://127.0.0.1:8447/health`，两者均返回 `Skill Atlas / ok / ready`；日志为 `early-tls.log`。该结果证明本机传输与健康接口，原生保存切换见 G1。
