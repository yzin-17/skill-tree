# 需求来源与决策依据

> 文档标识：`skill-atlas-v1-decisions`；首次创建：2026-10-29；最近更新：2026-10-30。

> 第一节保留既有需求；用户随后授权完成全部任务，选择推荐业务规则、Go 自管账号、本机安装及 Docker 后端，并要求后续直接采用推荐做法。
> 稳定规则与唯一未决问题清单在 [产品 Spec](../2026-10-29-skill-atlas-v1.md#questions)，当前任务和就绪证据在 [实施计划](../../archive/tasks/2026-10-29-skill-atlas-v1.md#current)。本文不维护另一套活动问题或任务状态。

## 1. 用户已经明确的要求

| 主题 | 已确定方向 |
| --- | --- |
| 平台 | 第一阶段 **macOS**，以后可能拓展其他平台 |
| 客户端 | 希望**原生开发**，不采用 Electron/Tauri 等跨端框架 |
| 云端 | 未来需要多端同步，因此加入后端 |
| 任务 | 强化手动创建；**不要周期待办、不要模板** |
| 任务与专注 | **一个任务可绑定多次计时**；支持正计时、倒计时、番茄钟 |
| 失败 | 任务可以失败，并统计成功率 |
| 经验 | **专注 1 分钟 = 1 XP；60 XP 升一级**；任务成功可以设自定义奖励级数 |
| 技能树 | 需要创建**子技能、前置技能**和跨技能树的绑定/关联 |
| 技能详情 | 选中技能用**右侧 Drawer**，不要把详情移到下方 |
| 视觉 | 技能树、成就希望更有游戏感，包含转职、称号 |
| 图标 | 对来源有明确诉求；不希望看起来像无规则的随机图标，应可手动选择和更换 |
| 布局 | 不追求自由拖拽，优先相对固定、易理解的布局 |

## 2. 已确认的实施方案

- 使用 **SwiftUI + 按需 AppKit**；原生 macOS 首发。
- Go 单体后端 + PostgreSQL，通过 Docker Compose 在本机运行；Go 自管账号，会话令牌默认仅内存，选择记住登录时使用 Keychain（2026-10-30 更新，见[当前登录规格](../2026-10-30-optional-login.md)）。
- SwiftData 缓存与本地计时现场，首版仅离线保障专注操作；其他数据写入走在线 API。
- 一个专注会话只给**一个主技能**累积时间 XP；任务成功奖励可以分配多个技能。
- 起始等级 **Lv.1**，每 60 XP 增加一级；显示进度 XP/60。
- 失败重试记录为多个 task attempts；成功率按成功/失败尝试次数计算。
- 已成功任务不直接重复成功结算；想再次练习可手动创建新任务。
- 前置关系首版按**软锁定**展示缺少条件，不强制阻止用户创建任务/记录专注。
- 星图自动布局，Drawer 右侧覆盖画布；图标用跨端 `icon_key` + macOS SF Symbols 映射。
- 职业/称号优先四类简单条件，不做复杂规则引擎或装备属性。
- 首版同一设备只运行一个活动中的计时器，不限制任务包含多少历史计时。

## 4. 实施阶段禁止擅自增加

- 周期任务、任务模板、强制目标规划、自动生成任务。
- 复杂多人系统、社交排行、付费商城、装备掉落。
- 微服务、消息队列、复杂离线协同或通用规则 DSL。
- 自由节点拖拽作为首版必需能力。
- 因“更炫酷”而牺牲 macOS 原生交互习惯、计时可靠性和结算一致性。

## 5. 维护规范

- 用户后续决定改变时，先更新 Spec 的当前规则/问题及对应附件，再更新 Task 的依赖与证据；本文只在确有需要时补充决定依据，不复制当前问题清单。
- 业务公式、状态转换、同步幂等与跨树关系一旦修改，需要同步更新验收用例。
- 视觉 Demo 只用作交互参考，不代表后端、原生能力或自动化测试已经完成。
- 未经确认的未来方向留在 Spec 的非目标或可选范围；当前首版未完成义务继续由 Task 持有，不通过 TODO 或归档制造完成。实际实施记录在有内容时写入支持文件，当前文档不预建空历史。
