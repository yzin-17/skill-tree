首次创建：2026-10-30  
最近更新：2026-10-31  
任务标识：backend-address  
状态：已验收，当前契约  
对应任务：[实施任务](../archive/tasks/2026-10-30-backend-address.md)

## 目标与范围

用户可以在设置和登录界面手动配置 Skill Atlas 后端地址，检查连接、保存、恢复默认，并在重启后继续使用。默认值来自应用包的连接配置，当前本机默认地址为 `https://localhost:8447`。

本次覆盖原生客户端配置、连接与切换生命周期。后端 API、数据库业务规则及部署方式采用现有契约；不部署外部服务或迁移业务数据。

## 地址与连接契约

- 沿用 HTTPS 要求，接受主机、可选端口及末尾斜线；去除首尾空白、统一主机大小写及默认端口。拒绝用户信息、查询、片段、非根路径和无效端口。
- 保存的是服务根地址，请求继续使用 `/health`、`/v1/...`。非法地址在发送前拒绝；请求和重定向均限制在配置的同一来源。
- 默认后端保持应用包证书校验；自定义后端接受系统信任的证书或与应用包相同且主机校验通过的本机证书。证书验证不可跳过。
- 检查连接只对输入地址发送无登录令牌的健康请求，验证 `service=Skill Atlas`、`status=ok`、`database=ready`。检查不修改当前后端；编辑后旧检查结果失效，迟到结果不覆盖新输入。
- 合法地址即使暂时无法连接也可以保存，登录页始终提供修改入口；连接失败给出中文错误并允许重试。

## 保存与隔离

保存后立即重建该后端的客户端、账号、缓存、同步和专注控制器，刷新界面状态，不要求退出应用。相同规范地址保存视为不变；恢复默认采用应用包默认值。

以规范地址形成稳定的后端标识。不同后端的记住登录偏好、钥匙串服务名、本机数据库与待上传队列分别保存；默认后端继续使用原目录和原会话偏好。切换前保存并暂停正在进行的专注；保存失败阻止切换。原后端记录保持在原目录，切回后可继续。

旧账号恢复、同步和请求在切换时失效，不能给新后端发送旧令牌或待上传数据。新后端只恢复其自身明确记住的会话，否则显示登录页。地址配置本身不启用钥匙串。

## 验收标准

| 标识 | 可观察断言 |
| --- | --- |
| AC1 | 设置及登录页可编辑、取消、保存和恢复默认；地址重启后保留 |
| AC2 | 地址规范化及非法输入拒绝符合契约，相同地址不会重置会话 |
| AC3 | 检查仅访问候选后端且无令牌；成功、失败、重试及迟到响应状态正确 |
| AC4 | 保存后所有功能使用新连接，旧请求与界面状态不能串入新后端 |
| AC5 | 后端间会话、缓存和待上传队列隔离；默认兼容原数据；专注暂停保存失败时不切换 |
| AC6 | HTTPS 信任、请求来源与重定向限制通过针对性验证 |
| AC7 | 本机原生完成默认地址→IP 地址→重启→默认地址，原账号历史可读，失败地址可从登录页修复 |

## 验证与边界

核心测试覆盖规范化、偏好持久化、命名空间、无凭据健康检查、迟到请求及会话停用；临时数据库覆盖同账号标识下的后端隔离与专注保留。Release 构建后，通过同一 Docker 后端的 `localhost` 与 `127.0.0.1` 两个 HTTPS 来源执行原生验收，并保留截图、构建编号及数据摘要。

本轮没有用户提供的外部后端，系统 CA 分支按 URLSession 默认信任处理实现并复核，不声明已验收任意公网服务。
