# 局域网私有 CA 访问规格

首次创建：2026-11-08；最近更新：2026-11-08。

对应任务：[实施任务](../tasks/2026-11-08-lan-private-ca.md)。

## 目标与边界

其他 Mac 首次信任私有 CA 后，使用稳定的 `.local` 主机名连接同一个 Skill Atlas 后端；服务端证书续期无需重新构建客户端。用户已授权在本机配置并启动该方案。

`https://localhost:8447` 和局域网默认端口 `8448` 统一使用现有私有 CA 自动签发、续期的证书。PostgreSQL 数据卷保持原样，数据库继续只映射回环地址。旧客户端通过自定义 `https://127.0.0.1:8447` 或局域网地址使用系统信任，无需更新安装包；旧版默认 `localhost` 的固定叶证书校验在切换后不再适用。

## 部署契约

- 使用 Caddy 的内部 CA 为 `localhost`、`127.0.0.1` 和局域网主机名签发并自动续期服务端证书。API 通过显式 `TLS_TERMINATED_BY_PROXY=true` 仅在 Docker 内部提供 HTTP，移除 API 的宿主机端口映射，消除旧上游证书的续期依赖。独立部署时默认仍强制 TLS。
- CA 私钥和签发状态存入独立、持久的 Docker 数据卷；仅导出公开根证书供设备安装。停止和再次启动不更换根 CA。
- 主机名默认来自 macOS `LocalHostName`，客户端使用该主机名的 `.local` 地址。适用设备需在可互通且支持 mDNS 的局域网；设备隔离和跨网段解析不在自动配置范围内。
- 本机系统信任通过显式命令安装；若操作系统要求交互认证则保留提示，不绕过权限。其他设备由用户导入公开根证书并设置信任。
- 后续构建将公开根 CA 作为内置信任锚，客户端按证书链、有效期与主机名验证，支持叶证书轮换；旧叶证书作为信任锚仍兼容。现有安装包不在本次重建范围内，使用自定义地址和系统根信任即可继续连接。
- 不自动更换现有 App 的后端偏好。切换到局域网地址仍遵循既有后端缓存与会话隔离契约。
- 脚本提供启动、停止、状态、健康检查、根证书导出和本机信任命令。常规后端启动和停止仍兼容原脚本。
- `local.py up` 启动 API 与统一 TLS 代理；`lan.py up/down` 通过切换代理站点配置启用或关闭局域网及下载入口，本机 `8447` 保持可用。
- 提供默认 `8081` 的 HTTP 根证书下载入口 `/root.crt`，供尚未信任 CA 的设备访问；HTTPS 入口也提供该路径。下载目录只含公开根证书，HTTP 不代理 API、不开目录列表、不挂载 CA 私钥。接收设备通过服务端独立提供的 SHA-256 核对证书身份。

## 验收标准

| 标识 | 可观察断言 |
| --- | --- |
| AC1 | 局域网 HTTPS 入口通过根 CA 严格校验后返回现有 API 的健康状态；原 `8447` 入口仍可用 |
| AC2 | API 无宿主机 HTTP 入口，外部 TLS 采用严格证书校验；CA 私钥仅保存在独立持久卷，导出的根证书与服务端签发链对应 |
| AC3 | 代理重建后根证书指纹不变，`8447` 和 `8448` 的证书均由 Caddy 自动管理；数据库容器与数据卷保持原样 |
| AC4 | 本机系统信任成功后，原生 URLSession 可通过系统信任连接新地址；不重新构建 App |
| AC5 | 提供其他 Mac 首次导入根证书、设置地址和连接检查的可执行说明；跨设备验证受设备可用性限制，明确记录证据边界 |
| AC6 | `localhost:8447` 与 `127.0.0.1:8447` 的 TLS 健康检查通过；API 无宿主机端口及旧证书依赖，原生客户端的自定义地址信任分支可连接 |
| AC7 | HTTP 下载无需预先信任 CA，下载字节与已信任根证书一致；私钥路径、遍历路径和 HTTP API 路径均不可读取 |
| AC8 | 当前源码以应用包中的根 CA 验证自动轮换的叶证书；错误的旧叶信任被拒绝，自定义地址仍可通过系统根信任连接 |

## 验证与限制

定向验证配置注入防护、无效端口拒绝、旧环境兼容和根证书幂等导出；真实 Docker 验证 TLS 链、主机名、重建后 CA 保留以及原入口兼容。通过原生 URLSession 验证系统信任；第二台设备不在当前控制范围时只提供操作材料，不宣称已完成跨设备验收。

自动续期依赖 Caddy 服务运行和持久卷保留。已消除原 API 手动证书依赖；根 CA 本身也有有效期，因此不承诺永久免维护。
